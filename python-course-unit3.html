文件操作与异常处理

本单元将深入学习Python的文件操作和异常处理机制，掌握文件读写、上下文管理器、异常捕获、日志系统等核心技能。这些是编写健壮、可靠Python程序的必备知识。

📁 3.1 文件读写操作

文件操作是Python编程中最基础也是最重要的技能之一。无论是配置文件、数据存储还是日志记录，都离不开文件的读写操作。本节将详细介绍Python中文件操作的各种方法，包括打开文件、读取文件、写入文件以及文件指针的操作。

🎯 学习目标

  • 掌握open函数的各种打开模式
  • 熟练使用read、readline、readlines读取文件
  • 掌握write和writelines写入文件
  • 理解文件指针和seek操作
  • 熟练使用with语句进行文件操作

3.1.1 打开文件（open函数）

Python使用内置的open函数来打开文件，该函数返回一个文件对象。open函数的基本语法是：open(filename, mode, encoding)。其中mode参数指定打开模式，encoding参数指定字符编码。

📌 文件打开模式

r - 只读（默认）
w - 只写（覆盖）
a - 追加
x - 新建文件（存在则报错）
r+ - 读写
w+ - 读写（覆盖）
a+ - 追加读写

📌 文本与二进制模式

t - 文本模式（默认）
b - 二进制模式
rb - 二进制只读
wb - 二进制只写
ab - 二进制追加

🐍 文件打开基础 - file_open.py

3.1.2 读取文件（read、readline、readlines）

Python提供了三种读取文件的方法：read()读取整个文件或指定字节数，readline()读取一行，readlines()读取所有行并返回列表。

🐍 文件读取方法 - file_read.py

3.1.3 写入文件（write、writelines）

写入文件使用write()方法写入字符串，writelines()方法写入字符串列表。注意write()不会自动添加换行符，需要手动添加'\n'。

🐍 文件写入方法 - file_write.py

3.1.4 文件指针与seek

文件指针标记当前读取或写入的位置。seek()方法用于移动文件指针，tell()方法返回当前指针位置。

🐍 文件指针操作 - file_seek.py

3.1.5 with语句与上下文管理器

使用with语句可以确保文件在使用后正确关闭，即使发生异常也不例外。这是处理文件的标准方式。

🐍 with语句与上下文管理器 - with_statement.py

⚠️ 3.2 异常捕获与处理

异常处理是编写健壮程序的关键。Python提供了强大的异常处理机制，能够优雅地处理程序运行过程中出现的各种错误。本节将详细介绍Python的异常处理语法和最佳实践。

🎯 学习目标

  • 理解Python异常的概念和分类
  • 掌握try-except结构的使用方法
  • 学会处理多个异常和使用else/finally子句
  • 掌握raise语句和自定义异常
  • 能够编写健壮的异常处理代码

3.2.1 常见异常类型

异常类型 描述 常见场景
SyntaxError 语法错误 代码书写错误
IndexError 索引越界 访问列表不存在的索引
KeyError 键不存在 访问字典不存在的键
ValueError 值错误 类型转换失败
TypeError 类型错误 操作类型不匹配
FileNotFoundError 文件不存在 打开不存在的文件
ZeroDivisionError 除数为零 除法运算除数为0
AttributeError 属性错误 访问不存在的属性
ImportError 导入错误 模块导入失败
RuntimeError 运行时错误 程序运行时错误
🐍 常见异常类型 - common_exceptions.py

3.2.2 try-except结构

try-except是Python异常处理的基本结构。将可能引发异常的代码放在try块中，异常处理代码放在except块中。

3.2.3 多个except子句与异常链

可以为一个try块编写多个except子句来处理不同类型的异常。Python 3还支持异常链，使用raise...from语法来保留原始异常信息。

3.2.4 else子句与finally子句

try-except结构还可以包含else和finally子句。else在try块没有异常时执行，finally无论是否有异常都会执行。

🐍 else与finally子句 - else_finally.py

3.2.5 raise语句与自定义异常

使用raise语句可以主动抛出异常。Python允许创建自定义异常类来处理特定的业务逻辑错误。
